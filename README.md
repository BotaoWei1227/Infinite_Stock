# 煉金交易所（玩家製作的非官方小遊戲）

## 架構（全部放在一個 Cloudflare Worker）
- `public/`：靜態網頁，由 Worker 的 Static Assets 提供。Google 登入用 Firebase Auth。不再串接《無限煉製》（沒有 OAuth、沒有工坊綁定）。
- `worker/src/`：API（`/inject`、`/craft`、`/trade`、`/bank`、`/monopoly` 等）。先驗證 Firebase ID Token（必須是 Google 登入），所有規則與漲跌都在伺服器計算。
- Firestore：客戶端唯讀（`firestore.rules`），行情與動態用 onSnapshot 即時更新；所有寫入只由 Worker 完成。
- Google API Key 由玩家輸入，只放 sessionStorage，每次投入時隨請求送到 Worker 轉呼叫 Gemini；Worker 不儲存、不記錄請求內容。

## 行情機制
- 公開行情放在 Firestore 單一文件 `market/state`（價格與最近 180 個走勢點），客戶端只需監聽 1 個文件。**上漲機率不在這裡**（見下方「機率保密」）。
- Cloudflare Cron Trigger 每分鐘檢查預定新聞與每日造物；每分鐘讓每檔股票隨機走一步（單步幅度 0.15–0.75%，含微弱均值回歸；比原本每 2 分鐘一步的幅度減半，讓每小時的漲跌節奏大致不變）。市場只在台北時間 09:00–24:00 開盤，休市時行情停止且交易區拉下鐵捲門。
- 機率偏移（bias）＝上漲機率 − 50%，由所有玩家共同推動，單次都很輕、總量有上限（`worker/src/logic.js`）：
  - 投入物品：物品**沒有固定歸屬**，可以投入任何一檔股票。消耗 1 個物品，AI（`judgeRelevance`）判斷「物品和這檔股票的主題有多相關」，先選分級（direct 85–100／strong 65–84／weak 20–45／none 0–15），伺服器再把分數壓進該級範圍；同一組（物品×股票）只判一次，結果存在私密集合 `judged/{雜湊}`。相關度高過門檻（預設 70，開發者可調）→ 提高上漲機率，沒高過 → 反而壓低（`nudge`，一次最多 ±`INJECT_MAX` 5 個百分點），再乘上物品品階的力道（`LV_POWER` = 0.5／1／1.25／1.5）。投入當下價格**不會**跳動；一般玩家只看得到相關程度，看不到機率與分數。沒有設定 AI 時：物品名稱和股票名稱相同才算直接相關。
  - 物品與合成：玩家背包 `inv` 是 `{物品名稱:{n 數量,e 圖示,lv 品階 0～3}}`。火、水、土、風是基礎元素（一個 10 元，`BASE_PRICE`），蒸氣與雷只能合成。**三物合成**（`/craft`）由 `gemini-3.6-flash` 憑聯想**自由創造一個新物品**（名稱 1～10 字、emoji、品階、一句煉金師解說；`craftJudge`），新物品可以再當材料。品階**不降級**：新物品的品階不低於材料、最多高 1 級（伺服器強制）。**同一個組合只問一次**：結果存在私密集合 `recipes/{雜湊}`，所有玩家得到一樣的結果；已創造的名稱登記在私密文件 `secret/items`（同名沿用登記的圖示與品階；最近 40 個名稱會告訴 AI 以鼓勵新點子）。AI 暫時失敗時回 503，材料不扣；沒有設定 `GEMINI_API_KEY` 時退回固定配方（`craftResult`）。舊版背包會自動轉成新格式。
  - 買賣：壓力看**這筆交易占全服持股的比例**：比例 × 30 個百分點（`TRADE_PRESSURE`），買為正、賣為負；全服持股不足 100 股時以 100 股當分母（`FLOAT_FLOOR`）。例如全服持有 1000 股，賣 900 股會重創（碰到 ±15 上限），買賣 1 股只有 0.03 個百分點。可自訂 1～100,000 股；小單也會累加，仍受總偏移上限約束。全服持股記在私密文件 `secret/odds.float`（買賣與黑道清空持股時更新；第一次沒有紀錄時掃描一次玩家資料建立）。只影響機率、不直接改價格，所以沒有「買進再賣出」的套利。
  - 全部加總最多 ±15 個百分點（上漲機率 35%–65%，`BIAS_CAP`）。
  - **衰減**：高於 50% 的機率每過 5 分鐘只剩 90%（往 50% 掉），低於 50% 的對稱地每 5 分鐘回升 10%；小於 0.5 個百分點就歸零（回到 50%）。按真實時間連續計算（`DECAY`、`DECAY_MS`），與排程間隔無關；機率條在兩次行情更新之間也會持續更新。

## 選單與頁面（左上角 ☰）
- 📈 交易區：股票視窗、投入元素、背包、全服動態；可自訂每次買賣的股數。
- 🏦 銀行：高利貸，利率 5%／24 小時（連續複利），可無限借款，但欠款超過 100 並連續超過 24 小時會被黑道抓走關押一天、資產重製；欠款從淨資產扣除。伺服器端 `/bank`（借款／還款／全額還清）。
  - 💰 存款（同一頁）：活存日利率 0.4%（隨時存取）；定存日利率 1.2%，鎖 3 天（`TD_DAYS`），到期自動轉入活存並改以活存利率計息；提前解約只退本金、利息作廢（以存入時間辨識是哪一筆，最多 20 筆）。利息按真實時間連續複利。存款計入淨值；被黑道找上時存款也一併清空。
- ⚗ 練金工坊：背包、材料店（買基礎元素）、三物合成、配方簿。
- 🏆 富士比排行榜：依淨資產（現金＋持股市值＋存款−欠款）列出前 100 名；由 Worker 彙整，只回傳排行榜欄位。
- 🕶 黑市：搶玩家花費 10,000，成功率 30%，可拿走對方現金的 30%；被捕機率 70%，另罰 10,000 並關押 24 小時，搶款不會轉出。搶銀行花費 5,000，成功率 10%，成功獲得 50,000；失敗會被捕、罰 10,000 並關押 24 小時。服刑期間不能操作；欠款觸發黑道時改為資產重製並關押 24 小時。
- 📊 股票分析師：花費 1,000～10,000 元估計單一股票目前的上漲機率；費用 1,000 時估計誤差可達 ±50 個百分點，10,000 時不超過 ±10 個百分點，低於 5,000 會被分析師嫌小氣。真實機率只在 Worker 讀取，回傳給玩家的是加噪聲的估計值。
- 📰 自動財經新聞：台北時間 10:00、14:00、18:00、22:00 各一則，由 `gemini-3.6-flash` 依「練金世界」世界觀撰寫連線報導，並對 1～2 檔股票微調上漲基準機率（依新聞嚴重程度 ±1～±30 個百分點，持續 4 小時）；影響只存在私密文件，公開新聞不含機率。需要 Secret `GEMINI_API_KEY`；沒設定時不會發布。

- 📰 新聞排程：開發者可在新聞表單設定台北時間發布時間；預定新聞與其機率影響先存於私密佇列，到時才發布並生效。可從開發者新聞表單取消尚未發布的項目。
- ⚙ 設定：玩家可自訂排行榜顯示名稱（1～20 字）；介面大小（小／中／大，存在瀏覽器），以及 Google API Key 設定入口。

## 機率保密：只有開發者看得到
- 玩家的投入/買賣偏移與財經活動的影響，都存在私密文件 `secret/odds`。`firestore.rules` 不開放 `secret`（預設拒絕），客戶端讀不到；公開的 `market/state`、`news`、`feed`、`players` 裡完全沒有任何機率資訊（測試會掃描所有公開文件確認）。
- 開發者用 `POST /odds`（伺服器驗證信箱）取得偏移與進行中的活動，前端據此畫出「上漲機率 🔒」條；一般玩家呼叫一律 403。投入元素的回應也只有開發者會收到 `up`。
- 舊版資料（機率放在公開行情裡）會在第一次排程/操作時自動搬進私密文件，並把公開文件裡的機率欄位清掉。**舊的 `feed` 紀錄可能還留有 `up` 欄位，公開可讀**；想徹底清除，可到 Firestore 主控台刪掉 `feed` 集合（它只是顯示用的最近動態）。

## 財經新聞與活動
- 選單 📰 財經新聞：列出新聞；**只有開發者**看得到發布表單，並可提前結束活動。
- 一則活動包含：名稱（≤40 字）、活動資料（≤600 字，可留空）、持續時間（1 分鐘～30 天）、各股票的**上漲基準機率影響**（個別選「漲 +x／跌 −x」，x 為 1～40 的整數）、普發現金（0～1,000,000）。
- 活動影響：期間內，該股票上漲的基準機率從 50% 變成 50±x%（玩家的投入/買賣偏移疊加其上，總機率限制在 10%–90%）；多個活動會相加；結束後自動恢復。影響只存在 `secret/odds`，**公開的新聞文件不含影響**，玩家只看得到名稱、內容、時間與現金。
- 普發現金：每位玩家在活動期間內可領一次（`/news` 的 `claim`）；領取紀錄存在玩家文件的 `claims`（保留最近 100 筆）。
- 純資訊活動（例如前情公告）：不選任何影響、不填現金即可，不佔用行情的活動名額（有影響的活動同時最多 20 個）。

## 開發者帳號
- 在 Cloudflare 新增 **Secret** `DEV_EMAILS`（開發者的 Google 信箱，多個用逗號分隔；要新增第二位時，把兩個信箱用逗號分隔後一併存入）。再新增 Secret `GEMINI_API_KEY` 給伺服器產生每日造物題目。**不要把機密寫進 `wrangler.toml`**：倉庫是公開的，而且 `[vars]` 會在每次部署時覆蓋網頁上的設定。
- 伺服器用 Firebase 驗證過的信箱（`email_verified` 必須為 true）比對；符合者投入元素不需要材料、不扣背包，冷卻 8 秒仍有效。全服動態會標上 🛠。

## 規則與介面
- 判定模型固定為 `gemini-3.5-flash-lite`（`worker/src/ia.js` 的 `MODEL`，玩家無法更改；要換成 `gemini-3.6-flash` 只需改那一行）。這兩個模型已停用 `temperature` 參數，請求中不要再帶。
- 買賣、銀行、合成、大富翁都只需要 Google 登入（玩家資料以 Google 帳號為鍵）。
- 自訂名稱與排行榜由已登入的 Worker API 提供；現有 Firestore 規則已禁止客戶端寫入並允許 Worker 服務帳戶存取，因此不需額外新增規則。
- 銀行可無限借款；欠款超過 100 並連續超過 24 小時，黑道上門：現金、持股、欠款全部歸零（現金回到 50），並在全服動態留下紀錄。
- 元素是消耗品：投入一次用掉 1 個；背包有幾個就能投幾次（每次間隔 8 秒冷卻）。
- 介面：每檔股票是一個像素風「電腦視窗」（可收合）；Google API Key 與判定模型收在右上角 ⚙ 設定內，並有按鈕連到 Google AI Studio 的 API Key 頁面。

## 部署（全程可在手機網頁完成）
1. Firebase：啟用 Google 登入、建立 Firestore、發布 `firestore.rules`，授權網域加入 Worker 網址（`alchemy-exchange.<你的子網域>.workers.dev`）。
2. Google Cloud：建立只有「Cloud Datastore User」角色的服務帳戶，下載 JSON 金鑰（不要放進 Git）。
3. Cloudflare：Workers & Pages → Create → Import a repository → 選此倉庫，專案名稱 `alchemy-exchange`（須與 `wrangler.toml` 的 name 相同），Deploy。再到 Settings → Variables and Secrets 新增 Secret `FIREBASE_SA`（整份 JSON）、`GEMINI_API_KEY`（每日造物產生用）與 `DEV_EMAILS`（多位開發者信箱以逗號分隔）。
4. （已移除）不再需要《無限煉製》的 Client ID 與 Redirect URI。
5. 不使用 Server API，也沒有獎勵功能。
